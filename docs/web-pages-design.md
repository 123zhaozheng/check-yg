# 智行卫士 — Web 端页面设计规范（Monochrome 单色风格）

> 面向行内审计专员的流水审查平台。本文档定义 Web 端的全部页面、用途、核心组件与单色视觉规范。
> 页面描述保持弹性，后端接口仍在优化期，页面与接口的对应关系以「业务实体」为单位，不强绑定具体字段名。
>
> 设计基调：**单色 / Monochrome**。用明度与对比代替色相建立层级，用排版与网格承载节奏，用线条与柔和阴影构造材质。
> 详见文末《单色设计系统》。

---

## 0. 信息架构总览

业务主链路：**登录 → Dashboard → 新建任务 → 任务详情(导入 → 清洗 → 分析 → 报告) → 审查/导出**。
围绕这条链路，页面分为四个模块：

| 模块 | 页面 | 数量 |
|------|------|------|
| A. 认证与外壳 | 登录、布局壳(侧栏+顶栏) | 2 |
| B. 总览与任务管理 | Dashboard、任务列表、新建任务 | 3 |
| C. 任务工作台（详情页内的子页/Tab） | 概览、数据导入、清洗标准化、AI 分析、审查报告、导出 | 6 |
| D. 辅助页 | 设置、空白/错误/404 | 3 |

**合计：9 个核心页 + 3 个辅助页。**
其中「任务详情」是一个壳页，承载 6 个工作台子页（以左侧二级导航或顶部 Tab 切换），它们共享同一个 `taskId`，构成产品的主战场。

> 设计原则：页面不按功能切，而按**用户在这个任务里"下一步要做什么"**切。审计专员的认知是线性的（先有数据、再清洗、再分析、再看报告），界面也应当线性推进。

## A. 认证与外壳

### A1. 登录页 `/login`

**用途**：审计专员进入系统的唯一入口。行内系统，强调严肃与可信，不需要花哨。

**布局**
- 全屏分两栏（桌面）：左侧 60% 为品牌区（浅灰底 + 极简的盾形/网格几何线条作为"卫士"的隐喻，粗体大字「智行卫士」+ 一行辅助语「流水审查 · 标准化 · 智能报告」）；右侧 40% 为登录卡片，纯白底、细边框、柔和阴影。
- 移动端折叠为单栏，品牌区缩为顶部一行。

**核心组件**
- 账号、密码输入框（细线下划线风格，focus 时下划线加粗变深灰）
- 「记住我」复选框、忘记密码链接（辅文灰，置于输入区下方）
- 主按钮「登录」：纯黑底白字，hover 时微微下沉 + 阴影加深；非禁用态不出现彩色
- 次按钮/SSO 入口（若行内有统一认证）：描边按钮，灰边白底

**单色要点**
- 没有任何强调色；错误提示用**深灰底 + 白字小条**或**加粗深色文字**，而非红色
- 品牌区可用极淡的灰度渐变（`#fafafa → #f0f0f0`）作为画布，绝不喧宾夺主

---

### A2. 应用布局壳（Shell，非独立页）

**用途**：登录后所有页面的承重结构。左侧导航 + 顶部栏 + 主内容区。

**结构**
- **左侧栏（约 220px，可折叠到 64px 图标态）**：纯白或极浅灰底，右侧 1px 细分隔线。导航项为一组：Dashboard、任务列表、新建任务；下方分隔线后是次级：设置。当前选中项用**左侧 3px 黑色竖条 + 浅灰填充背景**标识，不使用彩色高亮。
- **顶部栏（约 56px）**：白底 + 底部 1px 分隔线。左侧面包屑（如 `任务 / 2026-06-张某某 / 数据导入`），右侧为：搜索框（细边框、placeholder 灰）、通知钟、用户头像（灰底圆形 + 首字）。
- **主内容区**：浅灰画布（`#f7f7f8` 一类），内容卡片为纯白，靠 1px 边框与极柔阴影（`0 1px 2px rgba(0,0,0,0.04)`）分层。

**单色要点**
- 整个壳只允许三种明度：白(卡片) / 浅灰(画布) / 深灰到黑(文字与强调)。状态全靠明度差表达。

## B. 总览与任务管理

### B1. Dashboard `/`

**用途**：审计专员登录后的落地页，一眼掌握"我在审查什么、进度如何、需要我做什么"。

**布局**：上方四张 KPI 卡片 → 中间「进行中任务」列表 → 下方「最近报告」与「待我处理」两栏。

**核心组件**
- **KPI 卡片**（4 张，等宽）：「进行中任务数」「本月已完成审查数」「待处理告警数」「平均审查耗时」。卡片：白底、细边、标题为辅文灰小字 + 主数值为粗体大号黑字 + 同比小字（用 ↑/↓ 符号 + 灰度，不用红绿）
- **进行中任务列表**：表格形式，列为 `任务名 / 员工标识 / 渠道数 / 当前阶段 / 进度 / 更新时间`。「当前阶段」用**灰阶胶囊**（导入=浅灰、清洗=中灰、分析=深灰、报告=黑底白字）表示推进，天然无色也能体现进度
- **最近报告区**：3–5 条报告缩略行，右侧"查看"描边小按钮
- **待我处理**：待确认告警、待复核报告的清单，每条带「处理」主按钮

**单色要点**
- KPI 数值是页面唯一的"视觉重心"，靠字号与字重实现，不靠颜色
- 进度用灰阶胶囊递进——这是单色设计里用**明度梯度代替进度条彩色**的典型手法

---

### B2. 任务列表 `/tasks`

**用途**：检索、筛选、进入历史任务。承载所有审查任务的"档案库"。

**布局**：顶部筛选条 + 主表格 + 分页。

**核心组件**
- **筛选条**：状态(全部/进行中/已完成/已归档)、阶段、时间范围、员工标识/任务名搜索。筛选项为细边框下拉与输入框，激活态加粗边框
- **任务表格**：`任务名 / 员工标识 / 涉及渠道 / 创建人 / 当前阶段 / 状态 / 创建时间 / 操作`
  - 行 hover：背景由白变极浅灰 + 阴影微浮
  - 状态：灰阶胶囊（同上）
  - 操作列：「查看」主按钮（小号黑底白字）、「归档/删除」次按钮（描边灰）
- **批量操作**：勾选多行后顶部出现批量条（黑底白字浮条），提供归档/导出清单
- **分页**：极简数字分页，当前页用黑底白字方块

**单色要点**
- 表格是本页主角：靠行分隔线(1px 浅灰) 与表头加粗字保持秩序，避免斑马纹彩色

---

### B3. 新建任务 `/tasks/new`

**用途**：发起一次审查。填写任务基本信息、选择待审员工、可选预选渠道。**此页只建任务、不传文件**——文件在任务详情的"数据导入"子页上传，职责分离。

**布局**：单列居中表单卡片（最大宽 640px），分两段：基础信息、审查范围。

**核心组件**
- **基础信息**：任务名称、被审查员工标识（工号/姓名）、所属部门、审查期间(起止日期)、任务说明
- **审查范围**：预期涉及渠道的勾选（银行、支付、理财、证券等，按后端实际渠道枚举），仅作为"预期"，实际以导入为准
- **底部操作**：「取消」描边按钮 / 「创建并进入」主按钮（黑底白字，创建后跳转任务详情的"数据导入"子页）

**单色要点**
- 表单字段统一用下划线或细边框风格；标签为辅文灰，输入内容为深色
- 表单卡片用白底 + 细边 + 柔阴影，居中悬浮于浅灰画布上

## C. 任务工作台（详情壳 + 6 子页）

### C0. 任务详情壳 `/tasks/:id`

**用途**：承载一个审查任务的全部工作流。顶部为任务头（恒定），下方为 6 个子页（二级 Tab 或左侧二级导航）。

**任务头组件**
- 左：任务名 + 员工标识 + 审查期间（粗体标题 + 辅文灰副标）
- 右：当前阶段灰阶进度条（导入 → 清洗 → 分析 → 报告，四段，已完成段为黑、进行中为深灰、未开始为浅灰），以及任务状态胶囊
- 阶段进度条是**单色产品里最关键的导航/状态合一组件**，贯穿整个工作台

**6 个子页（Tab 顺序即业务顺序）**

| Tab | 子页 | 对应业务实体 |
|----|------|------|
| 1 | 概览 | 任务元信息 + 整体进度 |
| 2 | 数据导入 | 各渠道流水文件上传 |
| 3 | 清洗标准化 | 清洗规则与标准化结果 |
| 4 | AI 分析 | AI 审查与异常发现 |
| 5 | 审查报告 | 报告生成与人工复核 |
| 6 | 导出 | 报告/数据导出 |

---

### C1. 概览 `/tasks/:id` (Tab 1)

**用途**：本任务的全景视图。审计专员一进来快速判断"数据齐不齐、进行到哪、有没有大问题"。

**核心组件**
- **进度概览卡**：四段阶段进度（复用任务头组件的放大版），每段下方显示该阶段完成度小字
- **数据概览**：已导入渠道数 / 总文件数 / 已标准化记录数 / 发现异常数（四个小 KPI）
- **时间线**：任务内关键事件（创建、各渠道导入完成、清洗完成、分析完成、报告生成），纵向时间轴，节点为灰阶圆点，已完成为实心黑
- **快捷入口**：按当前阶段给出"下一步"主按钮（如未导入则"去导入数据"，已分析则"查看报告"）

**单色要点**
- 时间线节点用灰阶（未开始=空心灰圈、进行中=深灰实心、完成=黑实心 + 粗连接线）

---

### C2. 数据导入 `/tasks/:id/import` (Tab 2)

**用途**：按渠道上传流水 PDF / Excel，查看每个文件的解析状态。**此页是后端 MinerU 提取等能力的入口**，前端只管"传文件 + 看状态"，不关心解析细节。

**布局**：左侧渠道列表（选中某渠道）→ 右侧该渠道的文件区。

**核心组件**
- **渠道列表**：左侧纵向列表，每项 = 渠道名 + 已导入文件数小角标；选中项黑底白字或左侧黑竖条
- **文件上传区**：大号虚线拖拽框（拖入 PDF/Excel），下方"或点击选择文件"描边按钮
- **文件列表**：`文件名 / 类型(PDF|Excel) / 大小 / 解析状态 / 上传时间 / 操作`
  - 解析状态灰阶胶囊：待解析=浅灰、解析中=中灰(带极简转圈)、完成=深灰、失败=黑底白字"重试"
  - 失败状态是唯一允许"重"一些的视觉，但仍只用黑白：粗体 + 加深背景
  - 操作：删除(描边红替换为描边深灰 + 文字"删除")
- **批量**：可一次拖入多文件，自动按文件类型/命名归入渠道（若后端支持自动识别）

**单色要点**
- 拖拽框 hover/拖入时：虚线由浅灰变黑、背景由白变极浅灰——用明度变化表达"可放置"
- 进度/解析状态全部灰阶胶囊，禁止转圈用彩色

---

### C3. 清洗标准化 `/tasks/:id/clean` (Tab 3)

**用途**：把多渠道异构流水清洗成统一标准 schema，展示规则命中与清洗前后对照。**此页直接对应后端清洗/标准化逻辑**，是产品的"专业纵深"页。

**布局**：上方规则概览条 → 左侧规则/字段导航 → 右侧标准化结果表。

**核心组件**
- **清洗概览条**：原始记录数 → 标准化记录数 → 丢弃/异常记录数，三个数字用箭头串联，丢弃数用粗体深灰强调（不用红）
- **规则面板（左）**：清洗规则分组列表（字段映射、格式统一、去重、异常过滤等）。每条规则可展开看命中数量；命中数高者字重加粗
- **标准化结果表（右）**：统一 schema 的流水表（日期、收支方向、金额、对方、渠道、摘要…）。支持按字段筛选、排序
- **清洗对照**：点击某行可展开"原始 ↔ 标准"对照视图，左右双栏展示同一笔记录的原始字段与标准化字段，差异处用**底色浅灰高亮**标识
- **规则调整**：高级用户可在此微调规则（如调整阈值），改动后"重新清洗"主按钮（黑底白字）

**单色要点**
- 对照视图的差异高亮用**浅灰底 + 深色字**，而非彩色 diff
- 规则命中数用字重/明度强调，避免彩色徽章

---

### C4. AI 分析 `/tasks/:id/analyze` (Tab 4)

**用途**：对标准化后的流水跑 AI 审查模型，发现异常/风险点并展示。**对应后端 LLM 分析能力**。

**布局**：上方分析控制条 → 左侧异常发现列表 → 右侧异常详情。

**核心组件**
- **分析控制条**：「开始分析」主按钮、分析模式选择（快速/深度，描边单选）、上次分析时间、模型/参数显示（辅文灰）
- **分析进度**：进行中时顶部出现极简灰阶进度条 + 阶段文字（"正在生成向量" / "正在调用模型" / "正在归并异常"）
- **异常发现列表（左）**：按风险等级排序的条目，每条 = 标题 + 涉及金额 + 涉及记录数 + 风险等级
  - 风险等级用**灰阶 + 形状**双重编码：高=黑底白字方块、中=深灰、低=浅灰；不依赖红黄绿
  - 选中项左侧黑竖条 + 浅灰背景
- **异常详情（右）**：选中异常的完整解释——AI 推理摘要、关联记录列表、时间分布小图、置信度
  - 置信度用**水平灰阶条**表示（0–100%），深色填充越多置信越高
  - 「采纳为告警」「忽略」「添加备注」三个操作按钮
- **对话式追问（可选增强）**：底部输入框，审计专员可对当前异常向 AI 追问，回答以单色气泡呈现（AI 回答=浅灰底、用户提问=黑底白字）

**单色要点**
- 风险等级是单色设计最考验功力的地方：务必用**明度梯度 + 形状/字重**而非色相
- 图表（时间分布、置信条）只用黑白灰，柱/线靠密度与粗细区分

---

### C5. 审查报告 `/tasks/:id/report` (Tab 5)

**用途**：把分析结论汇总为正式审查报告，支持人工复核、编辑、定稿。**对应后端报告生成与复核流程**。

**布局**：左侧报告大纲 → 中间报告正文(可编辑) → 右侧复核批注栏。

**核心组件**
- **报告大纲（左）**：章节目录（概述 / 被审查对象 / 数据范围 / 异常发现汇总 / 风险评估 / 结论建议），可跳转、可拖拽排序
- **报告正文（中）**：富文本/结构化渲染，章节标题用粗体大字，正文规整排版
  - 异常条目以"卡片块"嵌入正文，每块含标题、金额、AI 结论、关联记录入口
  - 支持**行内编辑**：点击段落进入编辑，编辑态加细虚线框
  - 「重新生成本章」次按钮（描边），「重新生成全报告」次按钮
- **复核批注栏（右）**：审计专员/复核人对章节的批注列表，每条 = 批注人 + 时间 + 文本 + 解决状态(灰阶)；可新建批注、@他人
- **定稿操作**：顶部「保存草稿」次按钮 / 「提交定稿」主按钮（定稿后进入只读 + 加水印式"已定稿"灰阶标签）

**单色要点**
- 报告正文排版即主角：严格遵循标题层级与行距，像一份印刷工整的黑白年报
- 批注用左侧细灰竖线 + 浅灰底块，不使用彩色批注高亮

---

### C6. 导出 `/tasks/:id/export` (Tab 6)

**用途**：将报告与原始/标准化数据导出为多种格式，供归档与线下流转。

**布局**：单列卡片，分"报告导出"与"数据导出"两组。

**核心组件**
- **报告导出**：格式单选（PDF / Word / HTML），可选含批注/不含批注开关，「导出」主按钮
- **数据导出**：范围选择（原始数据 / 标准化数据 / 异常记录），格式（Excel / CSV），「导出」主按钮
- **导出历史**：下方列表展示本任务历史导出记录（格式、范围、时间、下载链接），每行"重新下载"次按钮
- **导出预览**：点击导出前可"预览"（报告前几页 / 数据前若干行），预览用单色渲染

**单色要点**
- 开关(toggle)用灰阶：关=浅灰底灰圆、开=黑底白圆，不使用彩色开关
- 导出进度用灰阶条 + 百分比文字

## D. 辅助页

### D1. 设置 `/settings`

**用途**：系统级配置。分 Tab：账户、审查参数、渠道与解析、集成与模型。

**核心组件**
- **账户**：个人信息、密码修改、登录设备
- **审查参数**：默认风险阈值、默认分析模式、清洗规则默认集
- **渠道与解析**：各渠道启用状态、MinerU/解析后端配置（地址、超时、重试）
- **集成与模型**：LLM 模型选择与参数、向量库、回调地址等
- 所有配置项用统一表单组件；修改后「保存」主按钮

**单色要点**
- 设置页是"安静"的页：大量表单 + 分组卡片，靠分组标题字重建立层级

---

### D2. 空状态 `/empty`

**用途**：任务列表为空、无搜索结果、新用户无任务等场景的统一空状态。

**核心组件**：居中极简线框插画（盾形/文件夹线条图）+ 一行标题 + 一行辅文灰说明 + 一个主 CTA 按钮（如"新建第一个任务"）。

**单色要点**：线框插画仅用 1px 灰线，不加填充，保持克制。

---

### D3. 错误 / 404 `/error`, `/*`

**用途**：404、500、无权限、接口失败。

**核心组件**：大号粗体状态码（404/500）+ 一句解释 + 「返回 Dashboard」主按钮 + 「返回上一页」次按钮。错误码用粗体黑大字作为视觉重心。

**单色要点**：错误也用黑白表达，避免红色带来的"慌乱感"，契合企业级冷静气质。

## 单色设计系统（附）

### 明度标尺（核心调色板）

```
#000000  纯黑 — 主按钮、标题、最强强调
#1f1f1f  深灰 — 正文主色
#595959  中灰 — 次级正文
#8c8c8c  浅中灰 — 辅文、placeholder
#bfbfbf  浅灰 — 分隔线、禁用
#e5e5e5  极浅灰 — 卡片边框、表格行线
#f0f0f0  画布灰 — 次级背景
#f7f7f8  画布底 — 主内容区背景
#ffffff  纯白 — 卡片背景
```

> 全站只允许使用以上 9 级明度。状态、风险、进度全部在这 9 级里映射。

### 状态映射规则（无彩色）

| 语义 | 表达 |
|------|------|
| 进行中 | 中灰胶囊 + 极简灰转圈 |
| 完成 | 深灰实心 / 黑底白字 |
| 失败/告警/高风险 | 黑底白字 + 粗体（最重视觉） |
| 中风险 | 深灰 |
| 低风险 | 浅灰 |
| 禁用 | 浅灰文字 + 浅灰边框 |
| 选中 | 左侧 3px 黑竖条 + 极浅灰填充 |

### 字体与排版

- 字体族：系统无衬线（`-apple-system, "PingFang SC", "Microsoft YaHei", Inter, sans-serif`），数字可用等宽（`"SF Mono", "Roboto Mono", monospace`）以对齐金额
- 层级：H1 28/粗 · H2 22/粗 · H3 18/粗 · 正文 14/常规 · 辅文 12/常规
- 行距：标题 1.3，正文 1.6，紧凑表格 1.4
- 网格：8px 基线，间距取 8/16/24/32/48

### 阴影与边框

- 卡片：`1px solid #e5e5e5` + `0 1px 2px rgba(0,0,0,0.04)`
- 悬浮：`0 4px 12px rgba(0,0,0,0.08)`（hover 时）
- 弹层/抽屉：`0 8px 24px rgba(0,0,0,0.12)`
- 禁止使用彩色阴影

### 交互反馈

- hover：背景白→极浅灰 + 阴影微浮
- active：轻微下压（`translateY(1px)`）+ 阴影减弱
- focus：1px 深灰外框 + 2px 浅灰光晕（不使用蓝色 focus ring）
- 选中：明度变化为主，辅以左侧黑竖条
- 加载：灰阶转圈 / 灰阶进度条，不用彩色 spinner

### 设计自检清单

- [ ] 移除所有彩色后，层级与节奏是否依然清晰？
- [ ] 是否有足够留白让用户呼吸？
- [ ] 标题、正文、辅文之间的黑白灰对比是否自然？
- [ ] 每个状态是否都能用明度/形状/字重表达，而不依赖颜色？
- [ ] 金额、日期等数字是否等宽对齐？

## 与后端的对应关系（弹性，后端优化期）

| 页面 | 主要后端能力（实体级） |
|------|------|
| 登录 | 认证/SSO |
| Dashboard | 任务聚合统计、待办、最近报告 |
| 任务列表 | 任务检索/筛选/归档 |
| 新建任务 | 任务创建(元信息 + 预期渠道) |
| 概览 | 任务详情、事件时间线 |
| 数据导入 | 多渠道文件上传、解析(MinerU 等)状态轮询 |
| 清洗标准化 | 清洗规则、标准化 schema、清洗前后对照 |
| AI 分析 | LLM 审查、异常发现、置信度、追问 |
| 审查报告 | 报告生成、富文本/结构化编辑、复核批注、定稿 |
| 导出 | 报告/数据多格式导出、导出历史 |
| 设置 | 渠道与解析配置、模型与参数、审查阈值 |

> 接口字段名以最终后端契约为准；本文档只锁定"页面 ↔ 业务实体"的对应，不锁定字段。
